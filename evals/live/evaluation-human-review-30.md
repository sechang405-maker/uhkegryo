# 실서비스 30문항 사용자 화면 검수

## 평가 범위

- 평가 서비스: [uhkegryo](https://uhkegryo.vercel.app/)
- 검수자: 오세창
- 평가 대상: **화면에 표시되는 LLM 출력과 텀카드 선택만**.
- 제외: HTTP·백엔드 응답, 상태 코드, 도구 호출, 재시도 횟수, worker 동작, 내부 출처 검증, Pin 검색·이미지·링크 품질, 비용·지연.
- 입력 기준: [`dataset.jsonl`](../dataset.jsonl)의 원본 30문항. 기준 commit: `8d36b268209dcbccc88fc7283412415b66cc4d77`.
- 이 문서는 원본 평가셋의 **화면 관찰 가능한 부분만 평가하는 별도 검수표**다. 원본 전체 계약 평가 또는 출시 게이트 통과를 의미하지 않는다.
- 카드는 화면의 라벨·쉬운 설명으로 비교한다. 아래 한국어 용어는 기대 개념을 설명한 것이며 화면의 정확한 라벨을 미리 확정한 것은 아니다. `term_id`는 기준 식별용이지 화면 노출 요구가 아니다.
- 화면 문구의 생성 주체가 LLM인지 고정 UI인지 단정하지 않는다. 사용자에게 보이는 출력 품질로 평가한다.
- 배포 버전이 입력 기준과 다르면 차이를 기록하고, 기대 개념을 임의로 바꾸지 않는다.

- 응답 원문은 화면 접근성 텍스트를 순서대로 전사했다. 서식·줄 배치는 캡처와 다를 수 있으며 고정 UI 문구도 포함될 수 있다. EVAL-07~09는 실제 응답 원문을 확보하지 못해 검수자 요약과 구분하고 설명 품질을 평가 불가로 처리했다.
- EVAL-27 선행 요청에서 처리 불가 안내가 표시돼 마른 체형·서기 카드가 표시되지 않았다. 후속 입력도 전송하고 표시된 응답을 따로 기록했다. 선행 조건이 성립한 검증으로 취급하지 않는다.
- EVAL-30에는 원문을 일반 입력했을 때 실제 나온 처리 불가 안내를 기록했다. 그 원인이 worker 중단인지 확인하지 않았고, 장애 fixture를 강제로 만들지 않았다.

## 작성 방법

1. 서비스에 접속하여 문항 원문을 입력한다. EVAL-27을 제외하면 새 대화에서 시작해 이전 문항의 영향을 피한다.
2. 화면 답변을 복사하거나 스크린샷을 남기고, 실제 선택 카드의 라벨·설명을 기록한다. 개발자 도구·API 응답·로그는 보지 않아도 된다.
3. 항목별로 `O`(기대 충족), `X`(기대 위반), `평가 불가`(조건 미발생·응답 미표시·화면 정보 부족)를 작성한다. 빈 칸은 미작성이다.
4. 정상 화면이 보이는데 필요한 카드·안내가 빠진 것은 X다. 서비스 오류로 출력 자체를 볼 수 없는 경우는 평가 불가로 기록하고, LLM 실패나 카드 선택 실패로 단정하지 않는다.
5. 종합 판정은 X가 하나라도 있으면 X, 모두 O이면 O, X 없이 평가 불가가 남으면 평가 불가다. 평가 불가는 통과나 0점으로 계산하지 않는다.
6. 모든 문항을 시도하되 내부 장애 조건을 억지로 만들지 않는다. EVAL-23~29는 일반 입력에서 보이는 출력·카드만 판정한다. EVAL-30은 원래 worker 장애 문항이므로 일반 입력 결과를 그 문항의 성공으로 기록하지 않는다.
7. 설명에서 금지 용어를 단순 비교·부정하는 것은 잘못된 카드 선택이 아니다. 금지 개념을 실제 선택하거나 근거 없이 확정했는지 구분한다.

이 검수표는 요청에 맞춰 O/X 방식만 사용한다. 원본 rubric의 0~2점 정성 평가나 추가 judge 합의는 이번 개인 화면 검수의 필수 항목이 아니다.
