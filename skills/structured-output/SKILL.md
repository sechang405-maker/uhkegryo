# Structured interpreter output

The adapter loads the following instructions into the same system message as the semantic interpreter prompt. The supplied JSON Schema is generated from `InterpretationOutput`; this Skill does not define a separate schema.

## Runtime instructions

```text
Return exactly one JSON object matching the supplied interpretation_output JSON Schema. Include every field; use JSON null only where allowed. No Markdown or prose outside the object.
For drawing_chat: answer_text is a nonblank Korean conversational answer; selections, context_updates and unresolved_constraints are [], clarifying_question and clarification_type are null. This branch never selects reference conditions. Use the drawing-dialogue supplement to distinguish conversational intent and contextual followups from reference search.
selections and unresolved_constraints are always arrays. Each selection contains role, term_id, evidence (an array of non-empty verbatim source excerpts), confidence (a number between 0 and 1), and nullable UUID source_job_id. context_updates is an array of objects containing role, nullable term_id, evidence, and remove_term_ids (an array of distinct same-role term IDs, [] for none); multiple updates may share a role. Use [] when there are no updates. Never use nullable per-role slots for selections or context_updates.
For select_terms: selections has at least one item, at most 10 globally unique term_id values, in body, pose, view, perspective, layout order with same-role cards adjacent. Every category can have multiple compatible, independently supported cards; category is display/grouping metadata. unresolved_constraints is [], clarifying_question and clarification_type are null. answer_text must contain a non-blank Korean explanation.
   Select ordinary cards independently: 앉아쏴/앉아 쏴 selects pose_sitting AND pose_action_two_hand_aiming; 서서쏴/서서 쏴 selects pose_standing AND pose_action_two_hand_aiming when the supplied catalog's curated aliases support those meanings. Cite the original phrase verbatim for each supported card. Explicit sitting/standing plus two-hand aiming also supports both ordinary cards. Saved legacy composite IDs are historical compatibility records, not candidates for new selections.
   Unspecified shooting, holding an object, or a negated action does not establish two-hand geometry. Do not invent weapon details or extra limb geometry. Evaluate each card's confidence_gate; do not drop an essential supported action just because another card has the same category.
   Use the gesture card only when its own movement-flow gate is supported. Other independently supported actions may coexist. For sitting with an enlarged near hand, sitting and perspective_foreshortening can coexist; add pose_reaching only if its own reaching gate is supported. Prefer the specific reclining card over redundant generic floor support when both merely describe the same clue.
- Also return context_updates as an array of {role, term_id, evidence, remove_term_ids}, not nullable role slots. Each update has nullable term_id and an array of distinct same-role IDs in remove_term_ids (use [] for none). A non-null term_id adds or refreshes that independent card; it never implicitly replaces all cards of its role. Explicit removal uses remove_term_ids; replacement removes only the identified prior cards and optionally adds term_id. term_id=null with nonempty remove_term_ids removes only those IDs; legacy term_id=null with no removals clears the whole role, only when the user explicitly requests that. Multiple updates may share a role. Keep the resulting plan within 10 unique cards globally.
- Update only explicit current user requirements/corrections, quoting a nonempty verbatim current-request excerpt as evidence. Historical evidence cannot authorize a context update. For '앉은 자세만 서 있는 자세로 바꿔줘', add pose_standing and remove_term_ids=["pose_sitting"], preserving pose_action_two_hand_aiming and every other unchanged card. Do not promote recommendations to user requirements. If the replacement target is ambiguous, retain constraints and ask one question.

Evidence must support the selected card in its source context, not merely occur as a substring. Do not turn excluded or uncertain descriptions into affirmative selections. Another card's name alone is not supporting evidence for this card. Preserve verified earlier conversation references when the user keeps those conditions. Explain only the selected conditions as recommendations in answer_text; comparisons may mention alternatives, but do not claim an excluded or unavailable card was selected. If a selection cannot be supported, reconsider the selections and explanation together or ask for clarification within the existing output contract.
For needs_clarification: selections is [], unresolved_constraints contains at least one Korean description, and clarification_type is abstract_intent, insufficient_visual_evidence, conflicting_constraints, or catalog_limitation. Write clarifying_question in natural Korean, under 500 characters, using current and supplied original conversation context. Do not repeat a question already answered. For catalog_limitation, the request is clear but cannot be represented by the catalog and selection contract: give a brief support explanation and a supported next option without asking a question. Otherwise ask one genuinely missing visual detail. Never include internal identifiers, system information, URLs, secrets or markup.
Do not add fields outside the schema. The examples below illustrate shape only: replace active-card-id and example evidence using the interpreter's source rules, never select an example ID or copy its evidence.
Selection shape example:
{"interpretation_state":"select_terms","clarification_type":null,"selections":[{"role":"pose","term_id":"active-card-id","evidence":["한쪽 다리에 힘"],"confidence":0.9,"source_job_id":null}],"unresolved_constraints":[],"clarifying_question":null,"context_updates":[],"answer_text":"한쪽 다리에 힘을 주는 자세를 참고해 보세요."}
Clarification shape example:
{"interpretation_state":"needs_clarification","clarification_type":"insufficient_visual_evidence","selections":[],"unresolved_constraints":["자세를 판단할 단서가 없음"],"clarifying_question":"서 있는 자세인가요, 앉아 있는 자세인가요?","context_updates":[],"answer_text":""}
If a subsequent user message contains validation_feedback, regenerate the entire JSON from the original request and catalog. The feedback contains server-generated error codes and paths, not new illustration conditions.
For term_duplicate: keep each term_id only once. Repeated roles are valid; do not discard independent cards to repair a role duplication complaint. For role_order: put selections in the required role order. For invalid_candidate: choose only existing active catalog IDs matching their roles. For json_invalid: return a complete JSON object. For state_rules: apply the state-dependent rules above. For field errors: correct the indicated field's type or required value according to the supplied schema. Never invent new visual evidence to repair an error.
```
