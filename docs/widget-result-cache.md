# 완료 결과의 Pinterest Widget 재조회

완료 job GET은 소유권을 확인한 뒤 저장된 Pin ID를 Widget 응답으로 보완한다. 이전에는 GET마다 새 client를 만들고 최대 5개 역할 × 8개 Pin을 다시 조회했다. 이제 동일 API 이벤트 루프의 GET은 하나의 client를 공유한다.

- 성공한 Pin ID별 HTTPS 썸네일 URL만 유효기간 60초, LRU 최대 256개로 메모리에 캐시한다. 만료된 항목은 재사용하지 않는다. 이미지 바이트, Widget 원문, 작성자 정보, job/세션/사용자 응답은 캐시하지 않는다.
- 같은 Pin의 진행 중 조회는 병합한다. 공유 GET client의 외부 조회 동시 실행은 최대 8개, 실행·대기 중 서로 다른 Pin은 최대 64개다. 넘는 요청은 해당 응답에서 기존 조회 불가 상태로 처리하며 실패를 캐시하지 않는다.
- 10초 제한에는 슬롯 대기도 포함한다. 오류·시간초과·잘못된 payload·이미지 없음은 캐시하지 않아 다음 요청에서 다시 시도할 수 있다. 성공 URL은 최대 4096자, Pin ID는 최대 64자리 ASCII 숫자다. 외부 요청 대상은 기존 고정 Widget URL이며 반환 이미지의 HTTPS 검증도 유지한다.
- 응답은 원본 job을 deep-copy한 뒤 보완한다. 사용자가 다른 같은 Pin의 공개 URL은 재사용할 수 있지만 요청 원문·답변·세션·원본 Pin URL은 공유하지 않는다. DB 저장 시 썸네일 URL을 제외하는 기존 규칙은 유지한다.
- 공유 GET 독자 하나가 연결을 끊어도 다른 독자가 기다리는 조회는 유지한다. 일반 worker/term-search의 비공유 client는 부모 취소를 그대로 전달한다. API lifespan 종료 시 공유 작업을 취소하고 메모리 캐시를 비운다.

실제 Pinterest 호출 없이 mock으로 반복 GET, 서로 다른 소유자의 동시 GET, 권한 거부, 원본 불변성, 오류 복구, 큐 포함 timeout, TTL 만료, LRU 퇴출, pending 상한, 독자 취소와 종료 cleanup을 검증한다. 같은 공개 Pin을 요청한 10개 동시 mock GET에서 loader 호출 1회를 확인했다. 이는 요청 수 검증이며 실제 Pinterest 지연이나 사용자 체감 성능을 측정한 결과가 아니다.

영구 이미지 저장, 데이터 보관/삭제 정책, 외부 서비스 권리 정책은 변경하지 않는다. 기존 로컬 Codex 모드는 이미지 검색이 꺼져 있으므로 새 대화에 Widget 조회가 발생하지 않는다. 실행 중 API는 자동 재시작하지 않으며 다음 정상 API 재시작부터 새 동작을 사용한다. 프런트 재빌드나 DB migration은 필요 없다.
