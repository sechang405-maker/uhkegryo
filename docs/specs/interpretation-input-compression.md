# 본문 해석 입력 압축

## Why
- 레퍼런스를 요청하는 사용자가 본문 해석을 기다린다. 기존 운영 표본의 입력은 약 24,000~25,500토큰이다.
- 역할별 출력 스키마가 정의와 슬롯에 중복되고, 동적 JSON에 불필요한 공백이 있다.
- 지표: 카탈로그/응답 스키마 전송 크기, 실제 모델 입력 토큰, 해석 지연, 유효 선택 및 원문 근거 통과율.

## Goal
- 활성 카드 전체와 판단 규칙을 보존하면서 중복된 스키마 및 JSON 구분 공백을 제거한다.
- 현재 전체 카탈로그의 응답 스키마 직렬화 크기를 기존 대비 30% 이상 줄인다.
- 기존 역할 슬롯·nullable·enum·required·숫자 범위·추가 필드 금지와 외부 배열 계약을 유지한다.
- 범위 밖: 카드 필터링, 문맥 요약/삭제, 프롬프트 의미/예시 변경, 모델 변경, 검색/UI 개선, 배포.

## What
- v4와 활성 카드 입력은 동일한 역할 슬롯을 참조형 스키마로 전달하고 기존 배열로 변환한다.
- 카탈로그, 서버 대화 문맥, 재검증 피드백 JSON은 문자열 내부를 바꾸지 않고 구분 공백만 제거한다.
- 일부 역할에 카드가 없으면 해당 슬롯은 null만 허용한다. 빈 카탈로그는 기존 배열 스키마를 유지한다.
- v0/v1 및 카탈로그 미제공 경로의 응답 스키마는 유지한다.
- 다른 역할의 ID, 임의 ID, 범위를 벗어난 confidence, 누락/추가 필드는 계속 거부한다.

## How
- `structured_output.response_format`에서 역할별 정의를 `$defs/{type}_{role}`에 한 번 생성한다.
- 역할 슬롯은 해당 정의의 로컬 `$ref`와 null의 anyOf를 사용한다. 사용하지 않는 기존 두 정의는 역할 슬롯을 만들었을 때만 제거한다.
- 카드 ID 순서와 모든 검증 속성을 보존한다. 기존 Pydantic/resolver 검증과 재시도는 변경하지 않는다.
- `llm.py`의 동적 JSON 직렬화에 `ensure_ascii=False, separators=(",", ":")`를 사용한다. 원문 문자열의 공백·줄바꿈·철자와 입력 순서를 유지한다.
- 저장소 System/User template과 Langfuse Prompt Management 작업은 변경하지 않는다. 이번 변경은 동일 v4 의미 계약의 전송 표현 압축이다.
- 새 테스트에서 로컬 참조를 확장해 기존 슬롯 정의와 비교하고, 실제 전체 카드로 크기 감소를 확인한다.
- 실제 모델 검증은 같은 입력/모델의 변경 전후 input_tokens와 latency를 기록한다. 실행할 수 없으면 미검증으로 명시하며 바이트 감소를 토큰/시간 감소로 해석하지 않는다.
- 검증 기록: [2026-10-06 변경 전후 비교](../../evals/interpretation-input-compression-2026-10-06.md).

## AC
- Given 현재 전체 카탈로그, When 전송 스키마를 직렬화하면, Then 기존 대비 크기가 30% 이상 감소하고 참조 확장 후 역할별 검증 제약이 동일하다.
- Given 역할별 모든 활성 ID와 null 슬롯, When 스키마/어댑터를 검증하면, Then 정상 선택과 명시적 역할 해제를 수용하고 잘못된 역할/ID·confidence·누락/추가 필드는 거부한다.
- Given 일부 역할만 있는 카탈로그 또는 빈 입력, When 스키마를 만들면, Then 없는 역할은 null만 허용하거나 기존 배열 계약을 유지한다.
- Given 한글·영문·인용부호·공백·줄바꿈이 있는 카탈로그/문맥/피드백, When 직렬화한 JSON을 복원하면, Then 모든 값과 순서가 기존과 동일하다.
- Given 모호함·충돌·선택·대화 근거·재시도 사례, When 기존 회귀 테스트와 압축 입력 테스트를 실행하면, Then 기존 검증과 결과 계약이 유지된다.
