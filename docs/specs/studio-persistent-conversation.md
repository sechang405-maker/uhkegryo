# Studio 통합 답변과 지속 대화

상태: 구현 전 설계 검토. 이 문서는 동작 완료나 테스트 통과의 증거가 아니다.

현재 작업 범위: 사용자 결정에 따라 프론트만 먼저 구현한다. `studio-conversation-ui.md`가 이번 구현 범위다. 아래 백엔드·DB·세션·요약 설계는 팀 백엔드 구현 이후 연결할 통합 목표이며 이번 작업으로 구현하지 않는다.

## Why

초보 사용자는 처음 설명한 캐릭터를 후속 질문으로 수정한다. 현재 UI는 선택 카테고리에 따라 설명이 교체되고, LLM에는 현재 요청만 전달되어 이전 조건을 이어서 해석할 수 없다.

## Goal

- LLM의 통합 답변을 사용자 메시지와 함께 대화 순서대로 표시한다.
- 같은 브라우저의 익명 쿠키로 새로고침·브라우저 재접속 후 같은 대화를 복원한다.
- 후속 질문은 같은 대화의 검증된 이전 조건을 반영한다.
- 로그인, 다른 기기 간 복구, 일반 지식 챗봇, 새로운 이미지 생성은 제외한다.

## What

1. 화면 진입 시 익명 소유자의 기본 대화를 조회하고 최근 메시지를 복원한다. 유효 쿠키가 없으면 빈 화면으로 시작한다.
2. 사용자 입력을 기존 비동기 job으로 제출한다. 처리 중 입력·답변을 중복 생성하지 않는다.
3. worker는 같은 대화의 선행 기록과 검증된 조건을 해석기에 전달한다.
4. 완료 시 하나의 통합 답변을 추가하고 왼쪽 검색 결과를 갱신한다.
5. 카테고리 스크롤은 헤더 검색어만 갱신한다. 통합 답변은 교체하지 않는다.
6. 홈 예시 카드의 단일 검색·카테고리 재검색은 대화 turn을 생성하지 않고 기존 대화를 유지한다.

검색 도구 실패는 이미지 영역에서 안내한다. 유효한 통합 답변과 이전 대화는 삭제하지 않는다. LLM 실패·안전 거절은 고정 안내를 표시하고 기존 조건을 갱신하지 않는다. 재접속 시 진행 중 job은 다시 polling한다.

## How

### 선택한 접근

기존 PostgreSQL의 jobs 원문·결과와 익명 세션을 사용한다. 브라우저 저장소만 사용하는 방식은 서버 LLM 맥락과 소유권 검증을 해결하지 못하므로 사용하지 않는다. 전체 이력을 매번 모델에 전달하는 방식도 입력 크기 증가 때문에 사용하지 않는다.

### 기존 계약과의 연결

- 세션 소유권·조회·이력: `conversation-sessions.md`의 owner/session 분리와 API를 따른다. 구현이 없는 계약을 이미 사용 가능하다고 표시하지 않는다.
- 맥락·조건: `conversation-context.md`의 최근 6개 종결 job, 역할별 조건, 미해결 질문, source_job_id 검증을 따른다. 과거 추천은 사용자 확정 사실로 승격하지 않는다.
- 장기 대화: `conversation-summary.md`의 2,000자 요약과 원본 보존을 따른다. 요약은 독립적인 의미 정답이나 조건 근거가 아니다.
- 보존 기간은 기존 계약의 마지막 활동 이후 달력 기준 3개월이다. 쿠키 삭제·만료·다른 브라우저에서는 자동 복구하지 않는다.
- 별도의 회상 검색 기능은 `conversation-recall.md`의 후속 작업으로 남긴다. 이번 목표는 후속 해석과 화면 복원이다.

### 통합 답변 계약

- InterpretationOutput과 AgentResult에 `answer_text` 문자열을 추가한다. 최대 4,000자이며 기존 저장 결과 호환을 위해 기본값은 빈 문자열이다.
- 모델은 선택한 용어의 쉬운 의미, 선택 이유, 혼동 주의점을 하나의 한국어 답변으로 작성한다. Pin URL·썸네일을 모델에 전달하거나 모델이 생성한 링크를 근거로 쓰지 않는다.
- 카드·역할·근거·조건 검증에 성공한 답변만 저장한다. 구조 검증만으로 문장 의미가 증명됐다고 주장하지 않고 사람 평가를 별도로 수행한다.
- `memory_answer`는 회상 전용 필드로 유지하며 일반 통합 답변에 재사용하지 않는다.
- 과거 결과에 answer_text가 없으면 기존 user_message 또는 고정 호환 안내를 표시한다. 새로운 LLM 답변인 것처럼 재생성하지 않는다.

### 저장·격리·실패

- 이력 API는 쿠키 소유권과 만료를 확인한다. 다른 소유자의 대화는 반환하지 않는다.
- 사용자 입력 원문은 기존 jobs 보존 정책을 따른다. 일반 로그·trace에는 대화 원문과 Pin 데이터를 추가하지 않는다.
- job 완료와 조건/요약 갱신은 기존 설계처럼 attempt·상태·lease를 확인하는 단일 transaction으로 처리한다. stale attempt는 대화 기억도 수정하지 못한다.
- UI는 서버 기록을 기준으로 복원하고 job_id로 중복 표시를 막는다. 이력은 페이지 단위로 조회하며 오래된 기록을 확인할 수 있어야 한다.
- DB migration은 운영에 자동 적용하지 않는다. 격리된 테스트 DB에서 검증한 뒤 별도 승인으로 적용한다.
- 더미 모드는 지속 대화 UI 확인용임을 표시한다. 더미 응답을 실시간 LLM·서버 저장 검증으로 보고하지 않는다.

### 구현 순서

1. 세션 소유권·이력 조회·만료 구현 → 격리 DB에서 재접속과 타 사용자 차단 확인.
2. 이전 조건·요약·통합 답변 연결 → 후속 수정, 출처 검증, stale attempt 차단 확인.
3. UI 대화 누적·복원·카테고리 분리 → 새로고침, polling 재개, 검색 실패 유지 확인.

각 단계는 독립 검토 가능하게 분리한다. 기존 작업의 변경과 섞어 일괄 commit/push하지 않는다.

## AC

- Given 완료된 대화, When 같은 브라우저에서 새로고침·재접속, Then 같은 메시지 순서와 통합 답변을 복원한다.
- Given 체형 조건이 있는 대화, When 포즈만 변경, Then 체형 조건을 유지하고 새 요청에서 명시한 포즈 변경만 적용한다.
- Given 이전 확인 질문, When 짧은 답변, Then 질문 맥락을 사용하되 근거 없는 조건은 확정하지 않는다.
- Given 완료된 답변, When 카테고리를 클릭·스크롤, Then 검색어는 변경되고 답변은 그대로다.
- Given 홈 카드 검색 또는 카테고리 재검색, When 완료, Then 새 대화 turn이나 대화 기록을 만들지 않는다.
- Given 유효한 통합 답변과 이미지 도구 실패, When 결과 표시, Then 답변을 유지하고 이미지 영역에 실패를 표시한다.
- Given 다른 소유자의 대화·만료된 세션, When 이력 조회·제출, Then 접근을 거부하고 기록을 노출하지 않는다.
- Given stale worker attempt, When 완료 저장, Then job 결과와 대화 기억을 함께 변경하지 않는다.
- Given 처리 중 새로고침, When 화면 복원, Then 해당 job polling을 재개하고 메시지를 중복 표시하지 않는다.
- Given 긴 대화, When 맥락 생성, Then 최근 기록·요약의 크기 제한을 지키며 원본 이력은 보존한다.
