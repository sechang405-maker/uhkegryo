# 통합 대화 프론트 — 백엔드 연결 전

## Why

캐릭터를 설명하고 후속 요청을 보내는 흐름을 확인해야 한다. 카테고리 선택마다 답변을 바꾸면 하나의 통합 LLM 답변을 표시하는 최신 방향과 어긋난다.

## Goal

프론트에서 사용자 요청과 통합 답변을 순서대로 누적한다. 기존 브랜드·독립 채팅 스크롤·하단 입력란·검색 기능을 유지한다. 백엔드 코드, 운영 DB, 실제 LLM 기억·서버 이력 복원은 이번 범위에서 제외한다.

## What

- 카테고리 스크롤·홈 카드 클릭·재검색은 검색어와 이미지 영역만 바꾸고 대화를 유지한다.
- 전송이 접수되면 사용자 메시지를 추가하고 polling 결과로 같은 turn을 갱신한다. 처리 중 새 요청으로 이전 polling을 끊지 않는다.
- 개발 더미 모드는 대화 UI용 고정 응답이며 이전 요청을 언급하는 후속 응답을 제공한다. 실제 의도 해석이나 LLM 기억으로 표시하지 않는다.
- 더미 대화만 같은 브라우저 localStorage에 최근 50 turn을 보관해 새로고침·재접속 후 복원한다. 이 내용은 서버로 전송하지 않으며 쿠키 세션과 별개다. 개인·민감 정보를 입력하지 않도록 안내한다.
- 실제 모드는 현재 탭의 응답만 누적한다. 백엔드 이력 API가 구현되기 전에는 재접속 복원을 제공한다고 표시하지 않는다.
- 저장 차단·손상된 더미 기록은 안전하게 기본 미리보기로 시작한다. 저장 불가 안내를 표시한다.

## How

- frontend/lib/conversation.mjs는 turn upsert, 답변 표시, 더미 기록 읽기·쓰기, 고정 더미 응답만 담당한다.
- turn은 `{id, request, job, demo, polling_stopped?}`다. 같은 id는 갱신하되 이전 turn은 유지한다. 서버 payload의 job_id는 제출 id와 대조한다.
- 상태 조회 실패 시 해당 turn에 polling_stopped를 보존한다. 새 요청·기록 열기가 전역 오류를 초기화해도 이전 turn의 중단 안내는 유지한다. 서버 job_status를 failed로 바꾸지 않는다. 같은 turn의 비종결 갱신은 중단 표시를 유지하고 실제 completed/failed 응답이 확인된 경우에만 해제한다.
- 통합 답변 연결 예정 필드는 `job.result.answer_text`다. 필드명은 팀과 합의한 뒤 해당 helper만 조정한다. 이 문서는 백엔드 계약을 변경하지 않는다.
- 실패/안전 거절/범위 밖/확인 질문/회상 응답을 먼저 상태에 맞게 표시한다. success/partial_result는 answer_text를 표시한다. 옛 응답은 user_message 또는 통합 답변 미연결 안내를 표시한다. 개별 term 설명을 합쳐 LLM 답변인 척하지 않는다.
- ConversationPanel은 누적 turn만 표시한다. galleryTerm과 의존하지 않는다. 답변은 plain text로 표시해 HTML을 실행하지 않고 줄바꿈을 보존한다.
- 더미 저장에는 요청과 표시할 응답만 포함한다. Pin·썸네일·토큰·실제 API 기록은 저장하지 않는다. 개발 전용 플래그를 그대로 유지한다.
- 홈 카드와 이미지 실패 안내는 왼쪽 영역에 유지한다. 확인 질문의 선택 버튼은 기존 입력 채우기 동작을 유지한다.
- 우측 채팅 스크롤바는 브랜드 붉은색(#e44b65) 손잡이와 연분홍(#f7e3e7) 트랙을 사용한다. 지원 브라우저에서는 너비 10px, 둥근 모서리를 적용한다. 입력란·왼쪽 영역의 스크롤 동작은 바꾸지 않는다.

## AC

- Given 두 요청, When 완료, Then 두 사용자 메시지와 두 통합 답변이 순서대로 유지된다.
- Given 동일 job polling, When 여러 번 갱신, Then 메시지가 중복되지 않는다.
- Given 통합 답변, When 카테고리 전환·홈 카드 검색·재검색, Then 답변 내용과 개수는 변하지 않는다.
- Given 더미 대화, When 새로고침, Then 최근 대화가 복원되고 더미·브라우저 저장임을 표시한다.
- Given 손상된 저장 또는 저장 불가, When 초기화, Then 화면이 중단되지 않는다.
- Given 실제 응답에 answer_text가 없음, When 완료, Then 미연결 안내를 표시하고 term별 설명을 답변으로 만들지 않는다.
- Given 이미지 검색 실패와 유효 answer_text, When 표시, Then 통합 답변을 유지한다.
- Given 처리 중 job, When 추가 전송, Then 기존 polling을 유지하고 중복 제출하지 않는다.
- Given 첫 job 상태 조회 실패, When 다음 요청 완료 또는 기록 열기, Then 첫 turn의 중단 안내가 유지되고 대기 표시가 다시 나타나지 않는다.
- Given 중단된 turn, When 비종결 응답 갱신, Then 중단을 유지한다. 실제 종결 응답이면 그 응답을 표시한다.
- Given 긴 대화, When 우측 스크롤바 표시, Then 브랜드 색으로 표시되고 입력란은 고정된 채 대화 영역만 스크롤된다.
