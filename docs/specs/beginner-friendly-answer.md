# 초보자용 통합 답변 표현 개선

## Why

- 그림 초보자가 검색 결과와 함께 전문 용어의 의미와 관찰 포인트를 이해해야 한다.
- 실제 로컬 답변에서 `body_slim`, `pose_contrapposto` 같은 내부 ID와 '선택했습니다'라는 판정 설명이 반복됐다.
- 내부 처리 과정을 설명하기보다 사용자가 그림을 그릴 때 활용할 설명이 필요하다.

## Goal

- `answer_text`에 내부 ID를 노출하지 않는다.
- 전문 용어의 한국어 이름, 쉬운 뜻, 레퍼런스에서 확인할 점을 자연스러운 통합 설명으로 전달한다.
- 기존 선택 결과, 구조화 출력, 검색어, 실패 계약은 유지한다.
- 범위 밖: 프론트 디자인, 카드 데이터 수정, 추가 LLM 호출 단계, 후처리 필터, 모델 기본값 변경.

## What

- 사용자 표현과 관련 용어를 자연스럽게 연결한다.
- 용어마다 '선택했습니다', '명확한 단서가 있어', '다른 항목은 제외했습니다' 같은 내부 판정 보고를 반복하지 않는다.
- 용어 뜻을 풀어 설명하고 제공된 카탈로그에 근거한 관찰 포인트를 안내한다.
- 공통 지침은 읽기 쉬운 짧은 문단으로 작성한다. 최신 main의 v4 전용 2~4문장·구체적 관찰점 마무리 지침은 유지하며, Markdown은 그 내용을 표시하는 서식으로 적용한다.
- 후속 수정으로 Markdown 작성 지침을 적용했다. 제목·최초 용어 강조·관찰점 목록·주의 인용은 필요할 때만 사용하며 상세 정책은 markdown-answer-guidance.md를 따른다.
- 애매한 조건은 확정하지 않고, 필요한 주의 사항은 유지한다.
- 정보 부족으로 질문해야 하는 경우 기존대로 `answer_text`는 빈 문자열이다.

## How

- `backend/services/llm.py`에서 시스템 프롬프트에 추가하는 `answer_text` 작성 지침만 수정한다.
- 내부 ID는 구조화된 선택 필드에 계속 사용하되 사용자용 `answer_text`에는 쓰지 않도록 지시한다.
- supplied catalog와 supported evidence만 사용하며 URL, Pin, 이미지 내용과 새로운 사실을 지어내지 않는다.
- 추가 호출이나 자동 재시도는 만들지 않는다. 기존 4000자 상한과 스키마 검증을 유지한다.
- 단위 테스트는 실제 adapter가 SDK에 보내는 시스템 메시지에 지침이 포함되는지 확인한다. 이 테스트는 실제 모델의 의미 품질을 증명하지 않는다.
- 동일 질문으로 실제 모델을 호출하고 화면에 표시된 답변을 별도로 검토한다. 호출 비용이 발생할 수 있다.

## AC

- **Given** adapter 생성, **When** 모델 요청 구성, **Then** 내부 ID 비노출, 쉬운 뜻과 관찰 포인트, 판정 보고 반복 금지 지침이 시스템 메시지에 포함된다.
- **Given** 정상 또는 부분 결과, **When** 답변 생성, **Then** 기존 통합 문자열과 출력 스키마가 유지된다.
- **Given** 정보 부족 질문 응답, **When** 답변 생성, **Then** 기존 빈 문자열 지침이 유지된다.
- **Given** '마른 체형의 캐릭터가 한쪽 다리에 체중을 싣고 서 있는 자세 레퍼런스를 찾아줘.', **When** 실제 로컬 호출, **Then** 화면 답변에 내부 ID가 없고 슬림과 콘트라포스토의 뜻 및 카탈로그 기반 관찰 포인트가 있으며 반복적인 선택 보고 대신 자연스러운 설명이 표시된다.

## 검증 상태

- 2026-10-02 사용자 명세 승인 후 구현했다. 커밋·push는 수행하지 않았다.
- 신규 테스트는 변경 전 지침 누락으로 실패했고 수정 후 통과했다.
- 관련 LLM adapter·response assembler 테스트: 69 passed.
- 백엔드 전체 테스트: 443 passed, 23 skipped, 5 warnings. 건너뛴 항목을 통과로 계산하지 않는다.
- `git diff --check` 통과. 테스트용 API 이미지를 재빌드했다.
- 실제 화면 요청은 `LLM_INVALID_STRUCTURED_OUTPUT`로 실패했다. 별도 adapter 진단 호출에서는 OpenRouter HTTP 402를 확인했다. 두 실패를 같은 원인이라고 단정하지 않는다.
- HTTP 402 확인 후 추가 호출은 중단했다. 개선된 실제 답변의 의미 품질과 화면 AC는 아직 미검증이다. 결제·크레딧 상태 해결 후 같은 질문으로 다시 확인해야 한다.
