# 카테고리 검색 모드와 도형화 도움말

## Why
초보자가 현재 검색 모드를 쉽게 구분하고, 모드별 실제 검색 결과를 비교할 수 있어야 한다.

## Goal
각 결과 행의 검색 선택을 `일반 · 스케치 · 도형화`로 통일한다. 세 모드 모두 실제 API 재검색을 수행한다.
도형화 도움말은 마우스·터치·키보드로 열고 닫을 수 있다. 카드 DB·서버·구도 내용은 변경하지 않는다.

## What
마지막 성공 모드는 브랜드 색상과 aria-pressed로 표시한다. 일반은 drawing, 스케치는 sketch, 도형화는 mannequinization으로 재검색한다. 현재 적용된 모드도 다시 누를 수 있다.
요청 중에는 해당 행의 세 버튼만 비활성화한다. 성공하면 실제 응답의 이미지·검색어로 해당 카드만 교체한다. 실패·빈 결과는 이전 이미지·검색어·성공 모드를 유지하고 실패 안내를 표시한다. 우측 대화는 변경하지 않는다.
다른 행의 상태는 유지한다. 기존 실패 안내와 화면 이동 시 취소 정책도 유지한다.
각 행의 모드 선택 옆 `?` 도움말(접근성 이름: 도형화란?)은 상단에 굵은 `도형화란?` 제목을 표시하고, 아래에 `몸을 상자·원통·구로 나눈 구조 참고 자료입니다.`를 표시한다.

## How
POST /api/term-search에 term_id와 suffix를 보내고 실제 응답을 사용한다. 개발 대화 더미 모드에서도 재검색은 실제 API를 호출하며 더미 핀을 재검색 성공으로 반환하지 않는다.
현재 원본 galleryRows 입력은 수정하지 않고 term_id별 override에 성공 결과를 저장한다. 화면 이동 시 기존 AbortController로 취소하고 늦은 응답을 무시한다. 검색 성공 시 해당 카드의 썸네일 실패 표시만 초기화한다.
도움말은 native details/summary로 제공하며 별도 API·검색 기록은 만들지 않는다.
문서의 click 이벤트에서 열린 도움말 밖의 클릭만 감지해 닫는다. 도움말 본문 안의 클릭과 summary의 기본 토글은 유지하며 이벤트는 차단하지 않는다. 화면 종료 시 리스너를 제거한다.
도형화의 접미사는 mannequinization, 스케치는 sketch를 유지한다.

## AC
- Given 임의 모드 결과, When 일반 선택, Then drawing으로 실제 API를 호출하고 성공 응답의 이미지·검색어를 적용하며 다른 행을 유지한다.
- Given 재검색 중, When 화면 이동, Then 요청 취소 후 늦은 응답이 새 화면을 변경하지 않는다.
- Given 개발 더미 화면, When 스케치·도형화·일반 선택, Then 실제 검색 API를 호출한다.
- Given 이미 선택한 모드, When 재선택, Then 새 요청을 전송하며 실제 결과가 같을 수도 있다.
- Given 검색 실패·빈 결과, When 응답 수신, Then 이전 이미지·검색어·성공 모드와 대화를 유지하며 실패 안내를 표시한다.
- Given 모드 선택, When 성공, Then 해당 모드만 aria-pressed=true이며 설명은 유지된다.
- Given 도움말 닫힘, When 클릭·터치 또는 summary에서 Enter, Then 설명이 열리고 다시 선택하면 닫힌다.
- Given 도움말 열림, When 내용 확인, Then 도형화란? 제목이 본문 위에 표시된다.
- Given 도움말 열림, When 도움말 밖을 클릭하거나 터치, Then 도움말은 닫히고 클릭한 요소의 기존 동작은 유지된다.
- Given 도움말 열림, When 본문 클릭, Then 설명은 유지된다.

## 검증 기록 (2026-10-01)

- 프론트 테스트 31건 통과, production build 성공.
- API 테스트 응답으로 세 suffix의 요청 payload와 새 Pin 교체, 같은 모드 재요청, 실패 시 원본 유지 검증.
- 로컬 실제 호출: 검색 API에 도달했으나 PIN_SEARCH_UNAVAILABLE, Pin/썸네일 0개. 실제 이미지 수집 성공은 미확인이다.
- 브라우저의 스케치 버튼에서 실제 로딩→실패 안내, 일반/스케치 재시도 가능, 우측 대화 유지 확인.
- 검색 검증용 로컬 서버는 DATABASE_URL=sqlite:///:memory: 설정으로 기존 worker를 비활성화했다. DB·LLM 호출은 검증하지 않았다.
