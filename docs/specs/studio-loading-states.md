# Studio 로딩 표시

## Why
실제 요청과 이미지 다운로드 대기 중 화면이 멈춘 것으로 보이지 않도록 한다.

## Goal
브랜드 색상의 세 점과 연한 분홍 스켈레톤을 공간에 맞게 표시한다. 진행률이나 처리 단계를 추측하지 않는다.

## What
- 첫 요청·단일 용어 검색: 이미지 영역 스켈레톤.
- 카테고리 재검색: 기존 이미지를 유지하고 작은 세 점과 검색 모드 안내.
- 채팅 요청·답변 대기: 답변 영역의 중간 크기 세 점.
- 썸네일·확대 이미지 다운로드: 해당 이미지 공간의 로딩 표시.
- 실패·중단·완료 시 로딩 종료. 더미에 인위적인 지연은 추가하지 않는다.

## How
공통 LoadingIndicator와 이미지 로딩 컴포넌트를 사용한다. 실제 비동기 상태에 연결하고 prefers-reduced-motion에서는 움직임을 끈다. 백엔드는 변경하지 않는다.

## AC
- 재검색 동안 기존 이미지와 검색어가 유지된다.
- 채팅 대기와 이미지 다운로드에 공간별 크기의 표시가 나온다.
- 오류·폴링 중단 후 계속 처리 중이라고 표시하지 않는다.
- 조회 중단은 메시지별로 보존한다. 새 요청 완료나 기록 열기 이후에도 이전 중단 메시지에 로딩을 다시 표시하지 않는다.
- 스켈레톤은 접근성 트리에서 숨기고 대기 문구는 읽을 수 있다.
- 움직임 줄이기 설정에서 정적인 표시를 유지한다.
- 프론트 테스트와 빌드가 통과한다.

## 검증 기록
- 2026-10-02: #94의 메시지별 조회 중단 상태를 반영했다. 503 조회 실패 뒤 두 번째 요청 완료, 중간 상태 갱신, 실제 완료 응답의 회귀 테스트를 포함해 37개 테스트와 production build가 통과했다. 이번 수정의 브라우저 E2E는 미실행이다.
- 2026-10-01: 프론트 테스트 34개 및 production build 통과.
- 브라우저: 재검색 중 세 점·기존 이미지 8개 유지, 실패 후 로딩 종료 확인.
- 캐시 이미지와 확대 이미지의 로딩 종료 확인.
- prefers-reduced-motion 에뮬레이션에서 animation-name: none 확인 후 설정 복원.
- 실제 LLM/작업 처리 대기는 현재 더미 UI 환경에서 실행 검증하지 않았다. 기존 요청·폴링 상태에 연결했으며 백엔드 통합 검증은 별도다.
