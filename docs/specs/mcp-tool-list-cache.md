# MCP 도구 목록 재사용

## Why

사용자가 레퍼런스를 요청할 때마다 같은 MCP 서버의 도구 목록을 다시 조회한다. 운영 trace 한 건에서 `mcp-tools-list`가 19.02초 걸렸다. 재조회 횟수와 검색 단계 지연을 측정한다.

## Goal

같은 worker gateway의 4시간 이내 반복 요청은 MCP 도구 목록 네트워크 조회를 0회 추가로 수행한다. worker가 job polling을 시작하기 전에 도구 목록을 사전 조회하고, 정상 운영 중에는 3시간마다 갱신한다. 만료 후 또는 목록에 없는 도구 요청 시 다시 조회해 최신 schema로 검증한다. 첫 조회와 실제 도구 호출 시간 단축은 이 변경의 보장 범위 밖이다.

## What

worker 시작 시 도구 목록을 조회하고 schema를 검증한 다음 job polling을 시작한다. 이후 4시간 동안 검증된 목록을 재사용하며, worker가 살아 있는 동안 3시간 간격으로 백그라운드 갱신한다. 동시 요청은 한 번만 조회한다. 만료·미등록 도구는 새 목록을 조회한다. 조회 실패나 잘못된 schema는 캐시를 갱신하지 않는다.

## How

- API와 MCP 서버 계약은 그대로 둔다. `McpToolGateway` 인스턴스별 메모리에 검증된 목록·만료 시각을 둔다. 만료 시각은 monotonic clock 기준이다.
- `asyncio.Lock`으로 동시 조회를 직렬화하고 lock 획득 후 다시 캐시 유효성을 검사한다.
- 도구 목록과 schema는 외부 호출자가 수정할 수 없도록 복사해서 반환한다. 실제 `call_tool`은 계속 원격 MCP 도구를 호출한다.
- 만료 또는 미등록 도구 요청에서 조회가 실패하면 오류를 그대로 전달한다. 조회 성공 후에도 도구가 없으면 기존 `not listed` 오류를 유지한다.
- worker는 시작할 때 30초 상한으로 사전 조회한다. 성공하면 첫 job의 도구 목록 조회는 로컬 캐시를 사용한다. 실패·시간 초과면 안전한 오류 유형만 기록하고 worker는 계속 실행하며, 다음 요청이 다시 조회할 수 있다.
- 3시간 간격의 갱신은 `refresh=True`로 새 schema를 검증한다. 실패해도 worker는 계속 실행하고 기존 만료 시각은 연장하지 않는다. 성공한 조회 뒤의 유효기간은 4시간이므로 첫 갱신 실패 시 기존 목록에는 최대 1시간의 여유가 있다. worker 종료 시 갱신 task를 취소하고 종료를 기다린다.
- 서비스 운영 시간은 09:00~21:00이지만 시작·종료 예약은 이 기능의 범위 밖이다. worker가 실제로 시작할 때 사전 조회하며, 09:00에 서버가 켜진다면 그 조회가 끝날 때까지 첫 job은 대기할 수 있다. 21:00 종료 후 캐시는 사라지고 다음 시작에 다시 조회한다.
- 운영 확인 시 Langfuse `mcp-tools-list`와 전체 요청 p50/p95를 변경 전후 비교한다.

## AC

- Given 같은 gateway의 4시간 이내 두 요청, When 백그라운드 갱신 전 도구 목록을 요청, Then 원격 `list_tools`는 한 번만 호출되고 두 요청의 목록이 같다.
- Given 캐시 만료 또는 캐시에 없는 도구, When 목록 조회 또는 도구 호출, Then 새 목록과 schema를 읽어 검증한다.
- Given 동시 첫 요청 둘, When 목록을 요청, Then 원격 조회는 한 번만 수행된다.
- Given 갱신 조회 실패 또는 schema 오류, When 다음 요청이 도착, Then 손상된 목록은 캐시되지 않고 다시 조회할 수 있다.
- Given 유효한 캐시, When 반환된 목록을 호출자가 변경, Then 이후 호출의 schema 검증은 영향을 받지 않는다.
- Given worker 시작과 정상 MCP 응답, When 첫 job polling 전에 사전 조회가 완료되면, Then 첫 job의 목록 조회는 추가 원격 호출 없이 캐시를 사용한다.
- Given worker가 3시간 이상 실행 중, When 주기 갱신 시각이 되면, Then 새 도구 목록과 schema를 조회하고 검증해 캐시를 갱신한다.
- Given 사전 조회 또는 주기 갱신의 실패·30초 시간 초과, When worker가 계속 실행되면, Then 안전한 오류 유형만 기록하고 job polling은 중단하지 않으며 다음 조회에서 복구할 수 있다.
- Given worker가 종료됨, When 취소가 전달되면, Then 진행 중인 갱신 task를 취소하고 기다린다.
