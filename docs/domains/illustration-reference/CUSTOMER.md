# Illustration Reference User Experience Map

초보자는 자연어로 원하는 캐릭터 레퍼런스를 설명하고, 서비스는 검수된 체형·포즈·시점·원근·구도 용어와 확인 지점을 제공한다. 단서가 부족하면 질문 하나로 보완한다. 검색 결과가 일부 없으면 사용 가능한 용어와 Pinterest 검색 URL을 보여 주며 검색 실패를 명확히 알린다. 최종 처리 실패에는 내부 원인 없이 일반 장애 안내를 표시한다.

| 단계 | 사용자의 행동과 불편 | 목표 제품 반응 |
| --- | --- | --- |
| 1. 의도 설명 | “힙한 자세”, “아래에서 올려다보는 느낌”처럼 체형·포즈·시점이 섞인 일상어를 쓴다. | LLM은 허용된 후보와 근거만 구조화하고, 단서가 없는 역할은 채우지 않는다. |
| 2. 조건 분리 | 전문 용어를 몰라 전체 문장을 Pinterest에 붙여 넣거나 검색어를 반복해서 고친다. | Pydantic·resolver가 `body → pose → view → perspective → layout`을 검증하고, 필요한 역할만 선택한다. |
| 3. 용어 확인 | 제안이 확정 진단인지 단순 후보인지 혼동할 수 있다. | TERM_CARD JSON의 쉬운 뜻·입력 근거·관찰 지점을 표시하고, 추측이 필요하면 질문 하나를 한다. |
| 4. 역할별 탐색 | 한 이미지에 모든 조건이 맞기를 바라지만, 실제 작업은 여러 자료를 조합한다. | 선택된 역할의 검색 계획과 provider 결과 또는 검색 불가 상태를 분리해 보여 준다. |
| 5. 러프 시작 | 검색 결과·Pin이 없거나 도구 오류가 나면 다음 행동을 알기 어렵다. | `PIN_RESULTS_EMPTY`, `PIN_SEARCH_UNAVAILABLE`, 일반 처리 실패를 구분하고, 용어·검색 URL 또는 새 요청 안내를 제공한다. |

카드 데이터는 JSON 카탈로그에서 시작 시 검증·메모리 로드한다. 이미지·썸네일 URL·Pin 메타데이터는 저장하지 않는다. 이 여정은 도메인 경험에서 출발한 MVP 가설이며, 아직 사용자 인터뷰 또는 사용성 측정 결과는 아니다.
