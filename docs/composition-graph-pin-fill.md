# 구도 통합, 그래프 노드 확대, 핀 보충

## 구도 통합과 기록 호환

정식 카테고리 값은 body/pose/composition/perspective다. 기존 view의 11개 카드와 layout의 2개 카드를 composition.json에 병합했다. 모든 82개 원본 카드의 ID, 검색 조각, 의존 관계를 보존한다. 별도 레거시 합성 자세 카드도 계속 읽는다. 과거 파일 두 개는 병합 파일로 대체하지만 카드 데이터는 삭제하지 않는다.

과거 API 입력 및 저장 결과의 view/layout은 읽을 때 composition으로 정규화한다. 과거 보드 정렬, 카드별 교체/보존 정보, 대화 조건, 회상 검색도 호환한다. 사용자 DB의 JSON을 재작성하거나 스키마를 변경하지 않는다. 새 응답과 프롬프트는 composition을 사용한다. 데모의 예전 문구도 fixture ID를 유지해 복원한다.

## 표시 노드

검수된 실제 카드만 사용한다. 체형 3→6, 자세 3→12, 투시 3→5, 통합 구도 5→13(기존 시점3+구도2). 전체 메인 용어 노드 14→36, 카테고리 노드 5→4다. 같은 이름의 카드를 합치거나 새로운 카드 내용을 지어내지 않는다. 증가한 노드는 제한된 3D 좌표로 배치하고, 투영 후 라벨 간격을 조정한다. 목록 보기에서도 전체 카드를 선택할 수 있다.

## 유효 이미지 최대 8개

삭제 표시의 확인 가능한 코드 원인은 Widget 빈 data와 Widget HTTP404/410을 실제 핀 삭제로 단정하던 처리였다. 이제 조회 불가로 분류한다. 빈 응답만으로 실제 삭제·비공개 여부는 확정할 수 없다. 과거 비공개 기록 ID의 외부 진단은 자동 승인 검토에서 거절되어 실행하지 않았다. 사용자가 본 개별 핀의 실제 상태나 검색 인덱스의 오래됨을 확인한 것으로 주장하지 않는다.

검색 한 번의 응답에서 후보 최대24개를 추려 ID를 중복 제거하고 필요한 수만 Widget에 전달한다. 동시에 최대8개, 최종 유효 이미지 최대8개다. 정상8개면 추가 후보를 조회하지 않는다. 숫자 핀의 일시 장애는 기존1회 재시도 한도에 따라 후보당 최대2회이며, 최악의 경우 Widget 요청48회 이내다. 검색+미리보기 전체25초 한도와 기존 전역 연결/동시성 한도를 유지한다. 403/429 이후 추가 조회를 중지하고 Retry-After를 지킨다. 제한된 검색 응답에 이미 포함된 검증된 공개 썸네일은 새 Widget 조회 없이 사용할 수 있다.

첫 응답 이후 브라우저 이미지 로딩이 실패하면 실패 이미지를 숨기고 기존 정상 이미지를 보존한 채 카드당 자동 보충1회, 선택적 수동 보충1회만 허용한다. 보충 요청 자체는 재시도하지 않는다. 제외 ID는 로컬 API/provider에서만 사용하고 검색 질의는 고정 카탈로그 조각이다. 화면 전환은 보충 예산을 초기화하지 않는다. 새 명시적 검색은 새 예산을 가진다. 후보가 부족하면 실제 개수만 표시하며 8개를 보장하지 않는다.
