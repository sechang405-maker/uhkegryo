# 이미지 갤러리 masonry

기존 CSS grid는 각 행을 가장 높은 카드에 맞춰 짧은 이미지 아래 공백을 만들었다. 각 카드를 가장 짧은 열에 놓고 컨테이너/카드의 ResizeObserver로 다시 배치한다. 원본 종횡비와 흰 배경은 보존하고 자동 crop을 하지 않는다. 열 너비는 동일하고 간격은 10px이다. 최소 열 너비 240px을 기준으로 좁은 화면에서는 한 열로 전환한다.

DOM/Tab/스크린리더 순서는 기존 검색 순서 그대로다. 최단 열의 top은 항목 순서대로 감소하지 않으며 동률에서는 왼쪽 열부터 놓는다. CSS columns 방식처럼 DOM을 열별로 재정렬하지 않는다. 이미지가 늦게 로드되거나 실패 카드로 바뀌고 목록 길이가 달라져도 크기를 다시 관찰한다. JavaScript가 적용되기 전에는 기존 grid를 fallback으로 제공한다. 추가 패키지나 이미지 변환은 없다.

배치 단위 테스트는 가변 높이, 화면 폭, 실패 대체 높이, 항목 증가에서 열간격과 겹침/순서/경계를 검증한다. 브라우저에서는 5→8개 항목 변경, 지연/실패 이미지, 키보드, 모바일 및 실제 CDN 이미지 로드를 확인한다.

검증 결과: 프런트 108개 테스트와 production 빌드 통과. 실제 앱에서 공개 썸네일8개 모두 HTTP200/실제픽셀 로드, 데스크톱·390px 모바일의 동일열너비/10px 간격 확인. 별도 fixture 브라우저에서 지연·실패 이미지, 5→8개 변경, Tab 순서, 터치 확대, 겹침 없음 확인. API/DB/컨테이너는 변경하지 않고 기존 앱 프런트만 백업·동기화·재빌드·재시작했다. 첨부 Library 읽기는 메타데이터와 캡션만 반환하여 전달받은 화면 설명과 실제 앱으로 검증했으며 스크린샷을 외부 업로드하지 않았다.

## 핀 실패 대응 제안 — 이번 변경에는 미구현

현재 `searxng_pinterest_search.py`는 빈 검색과 검색 불가를 구분하고, 내부 engine_attempts에는 timeout/rate_limited/access_denied/captcha/suspended/invalid_pin_urls 등의 원인을 기록한다. 단, HTTP 요청 예외에서는 timeout 외에 upstream_error로 묶는 경로가 있다. `failure_mapping.py`는 HTTP429를 구분하지만 provider의 최종 공개 코드는 대부분 PIN_SEARCH_UNAVAILABLE로 합쳐진다. 프런트 roleNotice도 일반적인 실패 문구를 표시한다.

| 유형 | 현재 의미 | 추천 표시/대응 |
|---|---|---|
| 진짜 0건 | 정상 빈 결과 또는 이미 본 Pin 제외 | ‘조건에 맞는 결과가 없습니다.’ 자동 반복 대신 용어/검색 모드 변경과 기존 Pinterest 검색 링크 제공 |
| 응답 형식/Pin URL 계약 오류 | malformed_response, invalid_pin_urls | ‘검색 서비스 응답을 처리하지 못했습니다.’ 서버 진단으로 분리, 같은 요청 무한 재시도 금지 |
| 일시 장애/timeout | 검색 불가 또는 Widget unavailable | 기존 성공 이미지를 보존하고 수동 다시 찾기 우선. 자동화한다면 제한된 1회 지수 지연+jitter, 전체 시간 예산 유지 |
| 429 | 앱 동시성 제한 또는 외부 rate limit | Retry-After를 반영한 대기 안내. 버튼 중복 클릭 방지. 즉시 반복/다중 엔진 폭주 금지 |
| 인증/접근 차단/CAPTCHA | 현재 공개 코드에서는 검색 불가로 합쳐짐 | ‘서비스에서 접근을 제한했습니다.’ 자동 재시도 중단, 사용자가 기존 Pinterest 링크로 직접 이동. 로그인 자동화·우회 금지 |
| 삭제/존재하지 않는 숫자 Pin | Widget의 정상 형식 빈 data만 deleted로 처리 | 해당 카드만 ‘핀을 사용할 수 없습니다.’ 표시하고 다른 카드는 유지. 브라우저 이미지 오류만으로 삭제 판정 금지 |
| e1/썸네일 캐시 만료 | Widget 미지원 공개 식별자, 60초 URL 캐시/프로세스 종료 후 복원 불가 가능 | ‘이 이미지의 미리보기가 만료됐습니다. 다시 검색해 주세요.’ 삭제와 구분. 재검색 및 원문/검색 링크 제공 |

권장 순서: (1) 사용자에게 보이는 실패 원인/만료 표시를 분리하고 기존 이미지를 보존한다. (2) Retry-After·중복 방지·사용자 요청형 재검색을 정리한다. (3) 필요성이 확인된 후에만 공개 URL 메모리 캐시 TTL을 제한적으로 늘리고 결과를 측정한다.

직접 Pinterest 링크는 앱 검색 장애에도 유용하지만 로그인이나 접근 제한을 없애주지는 않는다. 캐시 TTL 연장은 반복 호출을 줄이지만 오래된/만료 URL을 보여줄 수 있고 서버 재시작 후 복원을 해결하지 않는다. e1 ID는 재검색 시 바뀔 수 있어 숫자 ID와 같은 안정성을 전제하지 않는다. 영구 이미지 저장이나 자동 외부서비스 전환은 추천 범위에 포함하지 않는다. 이번 작업은 위 정책/API/캐시를 변경하지 않고 masonry만 구현한다.
