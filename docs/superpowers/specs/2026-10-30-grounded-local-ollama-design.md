# 근거 기반 로컬 Ollama 역할 분리 설계

## 목표

Ollama 경로에서 모델이 `InterpretationOutput`의 상태, term ID, 검색 권한과 최종 JSON을
결정하지 않게 한다. 서버가 활성 TERM_CARD의 한국어 라벨, 관찰점, confidence gate와
명시적 충돌 규칙으로 상태와 검색 후보를 정하고, 로컬 모델은 승인된 카드의 한국어 설명과
기존 `query_fragments` 중 사용할 조각만 제안한다.

## 검토한 접근

1. 모델이 term ID를 제안하고 resolver가 거부하는 기존 방식은 4B·9B 모두 의미 오류와
   교차 필드 오류가 많아 제외한다.
2. 별도 임베딩 모델로 카탈로그를 검색하는 방식은 새 런타임과 평가 범위를 늘리므로 이번
   단계에서는 제외한다.
3. 카탈로그 어휘를 코드가 점수화하고 작은 모델은 승인된 범위만 보강한다. 외부 의존성이
   없고 잘못된 후보를 fail-closed로 처리할 수 있어 이 방식을 채택한다.

## 구성 요소

### 결정론 카탈로그 계획기

- 입력을 정규화하고 TERM_CARD의 `label_ko`, `label_en`, `look_for`,
  `confidence_gate.require_any`와 비교한다.
- 정확한 라벨과 구체적인 다단어 단서를 일반 단어보다 높게 평가한다.
- 같은 역할의 가까운 후보가 충분한 점수 차이를 만들지 못하면 선택하지 않는다.
- 명시적 정면/후면 동시 요구처럼 양립할 수 없는 조건은
  `conflicting_constraints`, 구체적 시각 단서가 없으면
  `insufficient_visual_evidence`로 질문한다.
- 선택된 term ID, role, 입력에 실제 존재하는 evidence만으로
  `InterpretationOutput`을 서버가 조립한다. 모델은 이를 바꿀 수 없다.

### 제한된 모델 보강

- 모델 입력에는 사용자 문장과 서버가 승인한 카드의 한국어 이름, 평이한 의미, 관찰점,
  기존 검색 조각만 포함한다.
- 단순 스키마는 `answer_text`와 term별 `query_fragments`만 허용한다.
- 검색 조각은 카드에 이미 존재하는 문자열의 부분집합만 허용한다. term ID 중복, 미승인
  ID, 임의 검색어는 거부하고 카드 기본값으로 복귀한다.
- 설명은 한국어, 승인 카드 이름, 최소 한 개의 실제 관찰점을 포함해야 한다. URL, HTML,
  내부 ID 또는 검증할 수 없는 구조가 있으면 카탈로그 기반 결정론 설명으로 복귀한다.
- 모호함·충돌·근거 부족 상태에서는 모델을 호출하지 않는다.

### worker와 검색

- `LLM_BACKEND=ollama`에서만 새 adapter를 구성한다. OpenRouter와 Codex adapter는
  변경하지 않는다.
- worker는 해석과 함께 검증된 검색 조각을 받고 기존 resolver, 검색 provider,
  response assembler, 대화 메모리, 결과 카드 구조를 그대로 사용한다.
- 반복 검색, 취소, lease 회수, 실패 매핑은 기존 worker 정책을 유지한다.
- 개인 용어 생성 API 계약은 변경하지 않는다. 회귀 테스트로 기존 기능을 보호한다.

## 실패 정책

- 후보가 없거나 역할별 최고 후보의 차이가 작으면 검색하지 않고 질문한다.
- 모델 보강이 실패하거나 잘리면 승인된 term 선택은 유지하되 검색 조각과 설명만
  결정론 폴백을 사용한다.
- 검색 provider 실패는 기존 partial-result 사유 코드로 반환한다.
- 구조가 유효하다는 이유만으로 의미가 틀린 선택을 성공으로 세지 않는다.

## 평가

- 기존 30문항과 기대 의미를 변경하지 않고 4B·9B를 각각 context 4096,
  `reasoning_effort=none`, 동시 생성 1건으로 평가한다.
- 유효 JSON, 필수/금지 term 정확도, clarification 적절성, 설명의 한국어 여부와
  카탈로그 근거, 검색 조각 허용 범위를 별도 지표로 기록한다.
- 생성 단계 평가는 DB와 이미지 검색 없이 실행하고, 별도의 통합 검사는 격리된 fake
  repository/provider로 worker의 검색→조립, 반복·취소·실패 흐름을 확인한다.
- 기존 결과 폴더를 덮어쓰지 않고 이전 4B/9B 결과와 새 역할 분리 결과를 구분한다.

## 비범위

- 새 모델 설치, 유료 API 호출, 공개 기본 모델 변경
- 터널, 방화벽, secret, 인증 또는 Vercel 환경 설정 변경
- 공개 Vercel 화면에서 노트북 loopback으로 연결하는 작업
