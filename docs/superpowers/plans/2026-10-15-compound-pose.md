# 복합 자세 구현 계획

승인: 자세와 행동이 결합된 레퍼런스 요청의 선택·검색 구조 확장. 실제 Luna 호출 금지.

## 설계

기존 자세 슬롯에 무제한 다중 선택을 넣으면 기억·갤러리·역할 검색의 단일 슬롯 계약이 함께 깨진다. 문구별 별칭만 추가하면 검색어에서 행동이 누락되는 원인이 남는다. 따라서 버전 관리되는 pose_compositions 선언을 원본 활성 카드 두 개에서 하나의 복합 후보로 구체화한다. 최초 지원은 앉기/서기 + 양손 조준 두 조합이다.

원본 카드들은 수정하지 않는다. 조합 ID·표시 이름·표현 별칭만 선언하고, 검색 조각·관찰 지점·의미·선택 게이트는 두 원본에서 파생한다. 원본이 비활성/차단/역할 불일치/의존관계 불충족이면 시작을 거부한다. 임의 사용자 문구나 모델 출력으로 조합을 등록하지 않는다.

복합 후보는 기존 pose 슬롯 하나를 차지한다. API·MCP·worker가 공유하는 카탈로그에 포함되므로 검색과 스케치/도형화 재검색, 기억/복원에서도 같은 ID와 두 조건을 유지한다. DB 변경 없이 기존 결과도 호환된다. 앉아쏴는 승인된 정형 표현으로 두 조건을 나타내며 단순 앉기·물건 들기·부정 표현을 복합으로 추정하지 않는다. 구성요소 각각의 근거 확인은 모델의 의미 판단 책임이고 기존 원문/부정 근거 검증은 유지한다.

## 구현 순서

- [ ] 실제 카탈로그 복합 후보·검색어·원본 불변성과 잘못된 선언 거부 테스트를 먼저 작성/실패 확인.
- [ ] catalog_composition.py에서 선언을 검증·구체화하고 catalog_repository.py에서 연결. index.json에 두 조합을 명시.
- [ ] llm.py의 복합 후보에 구성요소·별칭을 전달하고 프롬프트/런타임 Skill에서 복합 우선 선택과 단일 선택 호환을 설명.
- [ ] term-search HTTP·worker·기억/복원 모의 회귀를 추가하고 실행. 별도 합성 브라우저에서 표시·재검색 확인.
- [ ] 구현분을 개인 main에 직접 반영하고 전체 검증/독립 리뷰/원격 CI를 이어서 확인. 결함은 후속 커밋으로 수정.
- [ ] 진행 중 요청이 없는지 확인 후 개인 로컬 앱 적용·health 확인. 실제 DB 내용·대화·비밀값·비용 설정 불변.

## 검증 한계

모의 해석은 선택 이후 두 조건이 검색까지 유지되는 것을 증명한다. 실제 Luna의 자연어 선택 품질과 실제 이미지의 적합도는 평가하지 않는다. 지원 목록 밖 조합은 기존 문맥 질문/지원 안내를 유지한다.
