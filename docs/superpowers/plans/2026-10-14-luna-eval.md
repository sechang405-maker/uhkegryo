# Luna interpretation evaluation implementation plan

> Execution: inline using executing-plans; independent read-only review after implementation.

**Goal:** Prepare a bounded, explicit 16-case synthetic Luna evaluation without calling a real model during preparation.

**Architecture:** A separate scripts/run_luna_eval.py loads only a committed synthetic dataset, the v4 prompt and local catalog. It calls CodexInterpretationAdapter directly, without a worker, database, search, history retrieval, retry or judge. Default invocation only prepares fingerprints; --execute is required for real subscription consumption.

**Tech stack:** Python, existing Codex adapter and Pydantic contracts, pytest mock transport.

## Constraints

- Do not alter the OpenRouter runner or running local app.
- Exactly 16 explicitly selected fixed case IDs; at most one generation per case.
- Record failures/timeouts, requested and verified model identity, commit provenance and actual content hashes. Usage and cost remain unknown.
- Never read .env, database, user conversations or auth files. Only the existing Codex runtime manages its ChatGPT login.

## Tasks

- [ ] Add failing tests for explicit selection, no-execute default, one-call bound, sanitized failure, unknown usage, fingerprints and mismatch grading.
- [ ] Add fixed dataset (6 clear, 4 boundary, 4 safety/scope, 2 synthetic-context cases) and runner with append-only per-run results and no automatic resumption.
- [ ] Test mock success, timeout, malformed output and configuration failure; run existing offline regression.
- [ ] Document invocation and limits, independent review, commit only new files to personal main, verify remote files and CI. No actual model execution until separate approval.
